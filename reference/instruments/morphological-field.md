# Morphological field (`morphological-field`)

- **Phenomenon sought:** The space of internally compatible configurations in a multidimensional problem that cannot yet be reduced to one quantitative objective.
- **Why use it:** Ordinary strategy and design discussion compares a few familiar bundles. A morphological field separates dimensions, preserves surprising states, records why pairs can or cannot coexist, and exposes configurations that discussion never assembled.
- **Operating range:** Use for bounded strategy, product, policy, organization, research, or architecture questions whose important dimensions can be expressed as finite state ranges. Do not use when the field is still unbounded, states are continuous without defensible intervals, one higher-order whole property decides viability, or participants cannot distinguish evidence from preference.
- **Input:** One provisional focus question; candidate parameters and states with source pointers; named content owners or evidence for compatibility judgments; and any known whole-property or higher-order constraints that pairwise assessment must not erase.
- **What changes:** The instrument discretizes a problem, then applies explicit judgments to direct cross-parameter state pairs. This makes a configuration space enumerable but may impose false precision or hide dependencies that only appear among three or more states.
- **Procedure:**
  1. **Freeze the provisional focus and authority.** State the question, intended use, current boundary, who owns process, who may make content judgments, and who will maintain the field. Do not ask the model to settle disputed content.
  2. **Build the field.** Propose a small set of parameters and mutually distinguishable states. Keep source-backed minority positions and wild cards. Add `none`, `not applicable`, or an equivalent off-switch when a range would otherwise choke every configuration. Mark inferred parameters and unresolved state meanings.
  3. **Review the field before reduction.** Check coverage, duplicated dimensions, non-orthogonal ranges, missing extremes, scale mismatch, and premature exclusions. Preserve deliberate overlap when it represents a real stakeholder conflict. Do not ban a questionable state merely because it seems unattractive.
  4. **Assess connectivity.** Decide which parameter pairs have a **direct** relationship worth assessing. Record why. Do not add a constraint between parameters connected only through other assessed relations; that can double-constrain the model.
  5. **Run Cross-Consistency Assessment.** For every connected state pair, record a degree such as `possible`, `boundary`, `unknown`, or `impossible`; type the rationale as formal, empirical, practical-normative, ethical-normative, or user-defined; attach its source or content-owner judgment; and retain reasons for open as well as excluded cells. Keep causal examples in the rationale without encoding causal direction as the relation itself.
  6. **Generate the reduced space.** Enumerate configurations containing one state from each parameter and remove only those containing an explicit impossible pair. Preserve the exclusion trace from each removed configuration to its judgment cells. Do not attach likelihood, desirability, or rank.
  7. **Audit the model.** Inspect the surviving/problem-space quotient, fully choked ranges, inactive states, identical assessment profiles that may justify a merge, and coarse states that need splitting. Test at least one manually reconstructed surviving configuration and one excluded configuration. List every known higher-order constraint that the pairwise model cannot represent.
  8. **Query without choosing.** Return a small unranked sample of structurally different surviving configurations, configurations satisfying user-declared filters, and any wild cards. Separate configuration compatibility from feasibility, evidence strength, preference, prediction, and recommendation.
- **Result:** Return the focus and authority contract; parameter-state field; direct-connectivity map; complete typed judgment ledger; reduced-space size and exclusion trace; model diagnostics; higher-order residual; unranked queried configurations; version; and unresolved cells. Label configurations as generated compatible forms, not predictions or recommendations.
- **Control:** Direct-only connectivity blocks duplicate constraints. Typed rationales keep evidence and values separate. Manual reconstruction checks the reducer. Choke, merge/split, and higher-order-residual checks expose bad discretization. A content owner must be able to correct every consequential judgment.
- **Common distortions:** Parameters merely rename an existing preferred plan; orthogonality erases stakeholder conflict; the LLM fills unknown cells confidently; every open cell is treated as equally plausible; pairwise compatibility is mistaken for whole-system viability; or the reduced field becomes a hidden ranking device.
- **Escalate / stop:** Use [`design-grammar`](design-grammar.md) when a whole property, transformation rule, or consequential overlap cannot be expressed pairwise. Use [`ground-condition`](ground-condition.md) when a boundary judgment needs external evidence. Stop when the field cannot be bounded, content authority is absent, rationales remain generic, or the higher-order residual contains the main question. When content authority is absent, return only a preparation artifact: the provisional focus, sourced draft parameters and states, unresolved definitions, a blank connectivity and judgment ledger, named missing authority, and the questions that authority must answer. Record the run as stopped or prepared, not completed; do not reduce the field or label any configuration compatible.
- **What it requires:** High model effort and one or more content-review passes. Software or code may enumerate configurations, but computation does not supply the judgments. Preserve the field and judgment ledger whenever later queries or revisions matter.
- **Execution placement:** **Hybrid.** The orchestrator owns the live focus, state definitions, user corrections, higher-order residual, and final return. A computational worker may enumerate and query configurations using only the frozen field and judgment ledger. Content experts or the user own direct compatibility judgments. Without that authority, the worker may prepare the field and blank ledgers but may not assess compatibility, reduce the space, query surviving configurations, or complete the instrument.
- **Distinctness:** Unlike [`design-grammar`](design-grammar.md), this instrument maps possible configurations of an open problem field rather than reconstructing one source system and its transformations. Design grammar may supply grounded parts, states, invariants, and higher-order constraints; the morphological field adds systematic pairwise reduction and querying. Unlike [`frame-projector`](frame-projector.md), it does not compress cases onto two axes.
- **Provenance:** This Field Lab port adapts General Morphological Analysis and Cross-Consistency Assessment as described by Tom Ritchey in [“Principles of Cross-Consistency Assessment in General Morphological Modelling”](https://www.swemorph.com/amg/pdf/amg-4-2-2015.pdf) and [“General Morphological Analysis as a Basic Scientific Modelling Method” workshop guidance](https://www.swemorph.com/amg/pdf/amg-6-2-2017.pdf). The LLM execution split and saved-result boundary are Field Lab adaptations; the donor methods did not publish this card.
