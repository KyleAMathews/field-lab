# Behavior chain (`behavior-chain`)

- **Phenomenon sought:** The route through which one bounded human action became possible or useful in its setting: prior vulnerabilities, a prompting event, reported links, the target action, and its immediate and later consequences.
- **Why use it:** A person may remember only the action and a broad explanation such as “I froze” or “I always do this.” A chain makes the smaller links available for correction and shows where several functions remain possible.
- **Operating range:** Use for one action, lapse, avoidance, escalation, or repeated move that the user owns and wants to understand. Work from one recent or well-recorded episode. Do not use to explain another person's conduct, assign fault, deliver crisis care, or press into material the user does not want to revisit. Do not use it to shift responsibility onto someone living under coercion, abuse, or another person's target conduct.
- **Input:** One behaviorally stated target action, a rough episode boundary, and the user's account or records. Ask for missing material one question at a time. Let the user set the depth and stop at any point.
- **What changes:** The operation slows a global account into a sequence and asks about thoughts, feelings, body sensations, actions, and environmental events. This can cue detail and impose order, so treat every link as reported or inferred rather than discovered.
- **Procedure:**
  1. **Set one target.** Restate one observable action in the user's words, bound the episode, and ask for correction. Do not bundle several problems into one chain.
  2. **Mark vulnerabilities.** Record conditions already present before the episode that the user thinks may have mattered. Keep context separate from cause.
  3. **Locate the prompting event.** Identify the event after which the chain began. If the boundary is unclear, preserve the alternatives.
  4. **Trace links in order.** Ask one question at a time for the next remembered environmental event, action, thought, feeling, or body sensation. Preserve the user's wording and mark gaps rather than filling them.
  5. **Record the target action.** State what the person did or did not do without a trait label or judgment.
  6. **Record consequences.** Separate immediate from later effects and effects the user wanted, expected, disliked, or noticed only afterward.
  7. **Offer competing functions.** State two or more plausible accounts of what the action changed, gained, delayed, escaped, communicated, or protected. Tie each to reported links and name evidence that would weaken it. Do not infer a hidden motive.
  8. **Return for correction.** Show the chain, gaps, and competing functions. Ask one correction question and stop. Do not move into solutions unless the user asks for that task.
- **Result:** Return the target boundary; vulnerabilities; prompting event; ordered, typed links; target action; immediate and later consequences; competing functional hypotheses; support and gaps; and the user's corrections. Label the user's inner experience as testimony and the functional accounts as hypotheses.
- **Control:** Keep the original account beside the chain. Mark each element as user report, record, or inference. Preserve alternate prompt boundaries and competing functions. The user, not the model, confirms whether the sequence fits.
- **Common distortions:** Recall becomes false precision; “vulnerability” becomes defect; consequence becomes intention; one plausible function becomes the reason; the chain becomes a long interrogation; context becomes blame; or the model moves from understanding to advice without permission.
- **Escalate / stop:** Stop when the user asks to stop, the target will not stay singular, recall no longer supports order, or continuing would require clinical care. A solution-focused operation may follow only by user request after the chain is corrected.
- **What it requires:** Several short exchanges or a source account collected by [`open-page`](open-page.md). Ask one question at a time and reflect personal material before probing. A Field Log helps only when the correction trail or source records need to persist.
- **Execution placement:** **Orchestrator.** Live contact and correction create the access. A fresh agent cannot recover unreported experience and should not infer it from prose. If live contact is unavailable, return a source-limited draft chain with gaps, not a completed reading.
- **Distinctness:** Unlike [`substrate-map`](substrate-map.md), this instrument includes user-reported internal links, prior vulnerabilities, consequences, and competing functions. Unlike a solution analysis, it stops before proposing repairs.
- **Provenance:** This is a nonclinical Field Lab port of DBT behavior chain analysis. It retains the donor practice's target behavior, vulnerability factors, prompting event, links, consequences, and solution boundary while narrowing the use to user-led inquiry. See the [Oxford Handbook of Dialectical Behaviour Therapy](https://academic.oup.com/edited-volume/38169/chapter/333011509) and [Behavioral Tech's chain and solution analysis training](https://behavioraltech.org/event/10-10-2022-strengthening-your-practice-of-dbt/). The Field Lab card and its LLM use have not been validated as therapy.
